## Размышления

Один hook гарантирует одинаковый первоначальный шаблон, но не может обеспечить
заполнение диалога: он не получает сообщения runtime. Поэтому контроль состоит
из двух независимых уровней: ближайшие `AGENTS.md` обязывают каждого агента
вести журнал, а валидатор делает нарушение видимым и блокирующим для передачи
результата по правилам проекта. Это максимальная гарантия, возможная внутри
репозитория; внешний runtime, который игнорирует проектные инструкции, не
может быть технически перехвачен локальным кодом.

Архивные отчёты не мигрируются: восстановление незафиксированных реплик
означало бы фабрикацию истории.

## Финальный вердикт

**Закрыто:** единый формат сделан обязательным через корневые и локальные
инструкции; новый валидатор проверяет root, backend, frontend и shared.

**Не закрыто:** интеграция в runtime сторонних агентов остаётся их обязанностью:
репозиторий не может запустить hook в процессе, который не выполняет инструкции.

**Что сломано:** архивные отчёты не проверяются умышленно; их нельзя безопасно
привести к диалоговому формату без исходных сообщений.

**С чего продолжать:** при подключении нового агентского runtime добавить
вызовы start/end hook в его lifecycle и передать точное имя модели через
`--agent`.
