### <AGENT ANSWER>
> Диагностика подтвердила, что frontend на порту 4173 отвечает `404` на auth-маршрут, тогда как API на порту 8080 принимает тот же тестовый запрос и возвращает ожидаемый `401` для несуществующей тестовой учётной записи. В работающей production-сборке отсутствует встроенное значение `http://localhost:8080`, поэтому она использует same-origin и ошибочно обращается к frontend-порту.

## Размышления

Причина — устаревшая или собранная без `VITE_API_URL` production-версия `frontend/dist`. Это не ошибка учётных данных и не ошибка auth-сервиса: запрос из браузера не достигает API. Переданные пользователем реальные секреты не использовались в диагностике и не включены в отчёт.

## Финальный вердикт

**Закрыто:** Установлена причина невозможности авторизации: запущенный frontend bundle направляет auth-запросы на `localhost:4173`, где API-маршрутов нет.

**Не закрыто:** Требуется пересобрать и перезапустить frontend штатной командой, чтобы `VITE_API_URL=http://localhost:8080` попал в production bundle.

**Что сломано:** В текущем `frontend/dist` отсутствует API origin; `POST /v1/auth/login` на frontend-порту возвращает `404`.

**С чего продолжать:** Остановить текущий запуск через `make down`, затем выполнить `make up`; после этого браузерный запрос должен уходить на `http://localhost:8080/v1/auth/login`.
