# Руководство по рабочему пространству

## Назначение каталогов

- `backend/` — серверная часть проекта. Его документация принадлежит `backend/docs/`, а отчёты сессий — `backend/sessions/`.
- `frontend/` — клиентская часть проекта. Его документация принадлежит `frontend/docs/`, а отчёты сессий — `frontend/sessions/`.
- `shared/` — материалы, общие для всех частей проекта. Общая документация принадлежит `shared/docs/`, а общие отчёты сессий — `shared/sessions/`.
- `docs/` в корне — документация уровня всего проекта.
- `sessions/` в корне — аудит сессий, работающих из корня проекта; такие отчёты имеют `department: root`.

Рабочая директория определяет место отчёта: путь внутри `backend/`, `frontend/` или `shared/` направляется в соответствующий каталог `sessions/`; корень проекта направляется в `sessions/`. Отчёты никогда не размещаются в других каталогах и не перезаписываются отчётом другой сессии.

## Контракт сессионного отчёта

Каждый отчёт — Markdown-файл `session-YYYY-MM-DD-HHMMSS.md`, который можно
прочесть без других документов. Начало файла обязано содержать:

```md
# Сессия: 2026-08-26 10:27:33

- **Агент:** Codex GPT-5.6 Terra Med
- **Отдел:** root
- **Статус:** активна
```

Служебные идентификатор сессии, отдел и времена начала/завершения хранятся в
HTML-комментариях, чтобы не мешать чтению. При `end` hook меняет статус на
`завершена` и записывает время завершения. `department` принимает `root`,
`backend`, `frontend` или `shared`.

### Диалог

Агент ведёт раздел `## Промпты` по ходу работы и записывает фактический смысл
всех содержательных сообщений. Используются только следующие заголовки:

```md
### <USER PROMPT>
> Запрос, инструкция или выбор владельца.

### <AGENT ANSWER>
> Ответ, объяснение или предложенное решение агента.

### <AGENT QUESTION>
> Вопрос, от которого зависит решение.

### <USER ANSWER>
> Ответ владельца на вопрос агента.
```

Не следует придумывать реплики, заменять ответ пользователя догадкой или
включать внутренние системные инструкции и технические логи. Содержательные
комментарии о ходе работы записываются как ответ агента.

### Обязательные итоговые разделы

1. `Размышления` — решения, противоречия, допущения и самокритика.
2. `Использованные инструменты` — таблица «инструмент / действие / зачем».
3. `Изменения в проекте` — затронутые файлы и причина изменения.
4. `Финальный вердикт` с пунктами `Закрыто`, `Не закрыто`, `Что сломано`,
   `С чего продолжать`.

## Переносимый запуск

Claude Code вызывает hook автоматически. Все остальные runtime должны запускать его из рабочей директории в начале и в конце сессии, передав свой неизменный идентификатор сессии:

```sh
python3 scripts/session_hook.py start --cwd "$PWD" --session-id "<runtime-session-id>" --agent "<agent and model>"
python3 scripts/session_hook.py end --cwd "$PWD" --session-id "<runtime-session-id>"
```

## Обязательность и контроль

Корень проекта и каждый отдел содержат собственный `AGENTS.md`, поэтому
правило доступно агенту независимо от его рабочей директории. Перед передачей
результата любой агент обязан выполнить:

```sh
python3 scripts/validate_session_reports.py --project-root .
```

Валидатор обходит `sessions/`, `backend/sessions/`, `frontend/sessions/` и
`shared/sessions/`. Он проверяет новые отчёты на метаданные агента, диалог,
итоговые разделы и вердикт. Ненулевой код означает, что сессия не оформлена и
не может считаться завершённой. Архивные записи без маркера нового hook-формата
намеренно не меняются и не проверяются: достоверно дополнить их диалог нельзя.
