# Контекст продукта: управление продуктами с ограниченным сроком годности

## Цель

Помочь пользователю вовремя использовать продукты, срок годности которых скоро истекает. Продукт должен снижать пищевые отходы и необязательные траты на замену имеющихся продуктов, а также уменьшать риск употребления просроченной еды за счёт явного учёта указанных сроков годности.

## Целевая аудитория и приоритет

Первый пользователь MVP — один человек, который готовит дома в собственной квартире или доме. Семьи и небольшие заведения общественного питания важны, но отложены как последующие сегменты для отдельного исследования и не определяют объём MVP.

## Пользовательский поток MVP

1. Пользователь вручную добавляет продукт и срок годности — это обязательный базовый сценарий.
2. Пользователь может сфотографировать упаковку как ускоренный сценарий ввода.
3. OCR извлекает текст с фотографии, а LLM API разбирает его в структуру продукта.
4. Приложение подставляет результат в поля ручной формы.
5. Пользователь проверяет данные и выбирает `approve` для сохранения либо `reject` для отмены/исправления.

Фото и LLM не должны сохранять продукт без подтверждения пользователя: ручная проверка является защитой от ошибки распознавания срока годности.

## Уведомления и рецепты

- MVP отправляет уведомления на e-mail.
- Логика уведомлений зависит от группы продуктов: для каждой группы требуется свой срок предупреждения.
- Пользователь обязан иметь возможность изменить срок уведомления; минимальный допустимый порог — один час.
- После уведомления приложение должно предлагать рецепты на основе одного продукта, а предпочтительно — группы имеющихся у пользователя продуктов.

## Учётная запись

Для MVP пользователь регистрируется и входит по e-mail и паролю без подтверждения адреса. Верификация e-mail — обязательная задача после проверки MVP. При записи e-mail приводится к нижнему регистру; база данных должна обеспечивать уникальность нормализованного адреса.

## Регуляторная локализация срока годности

Интерпретация даты истечения срока годности зависит от регулятора, применимого к локации пользователя. В MVP пользователь выбирает страну из списка, а приложение сопоставляет страну с группой регулятора и применяет соответствующее правило отображения и смены статуса продукта.

Предположение владельца продукта о том, что в ЕАЭС срок истекает в 00:00 указанной даты, не подтверждено и не должно использоваться как реализованное правило до проверки первичных регуляторных источников. Исследование должно определить для каждой поддерживаемой регуляторной группы: момент истечения, применимость к разным категориям продуктов и способ корректно объяснить правило пользователю.

В MVP пользователь выбирает тип указанной на упаковке даты:

- `use by` / «годен до» — дата безопасности; после неё продукт получает статус «просрочен», визуально отмечается и исключается из рецептов;
- `best before` / «лучше употребить до» — дата качества; после неё приложение отправляет уведомление и визуально отмечает продукт, но оставляет его в списке и рецептах для осознанной проверки пользователем.

Это правило основано на различии дат в праве ЕС и требует отдельной проверки для остальных групп регуляторов. Источники: [Регламент (ЕС) № 1169/2011](https://eur-lex.europa.eu/legal-content/EN/TXT/?uri=CELEX%3A32011R1169+) и [разъяснение Европейской комиссии](https://food.ec.europa.eu/food-safety/food-waste/eu-actions-against-food-waste/date-marking-and-food-waste-prevention_en).

## Открытый вопрос для frontend

Мобильные push-уведомления являются желаемым каналом. До включения в MVP frontend-специалист должен подтвердить техническую возможность, поддерживаемые платформы, разрешения пользователя, фоновую доставку и оценку трудозатрат. До этого решения MVP ограничивается e-mail.

## Будущие гипотезы монетизации

- Предложение доставки продуктов, которые нужно использовать в ближайшее время.
- Купоны и скидки на продукты в онлайн- или офлайн-магазинах.

Эти гипотезы не входят в MVP и требуют отдельной проверки ценности для пользователя, экономической модели и соответствия требованиям к рекламе.

## Требующие исследования вопросы

- Набор групп продуктов и безопасные значения предупреждений по умолчанию.
- Регуляторные правила срока годности для стран и групп регуляторов, начиная с ЕАЭС.
- Список стран MVP и их сопоставление с группами регуляторов.
- Бесплатные OCR-библиотеки для распознавания текста на упаковке.
- Использование LLM API для извлечения структурированных полей и оценка ошибок.
- Критерии качества распознавания и допустимые сценарии отказа.
