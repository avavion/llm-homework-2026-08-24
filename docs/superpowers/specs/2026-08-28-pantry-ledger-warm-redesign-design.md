# Pantry Ledger — тёплый домашний редизайн

## Цель и границы

Обновить всё визуальное представление MVP Pantry Ledger, не меняя маршруты, API-контракты, правила сроков, переводы и бизнес-логику. Пользователь за несколько секунд понимает, что использовать первым, безопасно добавляет продукт и видит ясное значение каждого статуса.

Визуальный образ — «тёплая кладовая»: светлая, спокойная и домашняя, но не декоративная. Основа — кремовые поверхности, шалфейный зелёный, крупная читабельная типографика и очень умеренная глубина. Янтарный и красный не используются как декоративные акценты: только для сроков и разрушительных действий.

Не входит: тёмная тема, изменения API, новые продуктовые сценарии, push-уведомления, внешние рецепты и переработка доменной модели.

## Принципы

- **Сначала действие.** Лента «Использовать первым» появляется до полного инвентаря и содержит не более трёх позиций.
- **Тепло без инфантильности.** Serif работает только как display-шрифт; данные, формы и навигация остаются предельно функциональными.
- **Статус читается без цвета.** У каждого статуса есть текст, значок и семантический фон.
- **Одна главная CTA.** На экране основной кнопкой остаётся «Добавить продукт»; жизненный цикл продукта остаётся вторичным контекстным действием.
- **Одинаковая логика на всех экранах.** Форма, черновик фото, рецепт и настройки используют те же поверхности, расстояния, focus и состояния.

## Визуальная система

### Токены

| Роль | Значение | Применение |
| --- | --- | --- |
| Canvas | `#F8F6EF` | Фон приложения |
| Surface | `#FFFDFA` | Списки, формы, sheet и диалоги |
| Rail | `#F0F1E9` | Desktop-навигация |
| Ink | `#273129` | Основной текст |
| Muted | `#758074` | Вторичный текст |
| Brand | `#506D48` | CTA, активная навигация, позитивное действие |
| Brand soft | `#DFEAD5` | Лента срочности и спокойные акценты |
| Attention | `#A4671D` | `best before` после даты и предупреждения |
| Attention soft | `#FFF1DC` | Фон предупреждения |
| Danger | `#B7473D` | Просроченный `use by`, destructive action |
| Danger soft | `#FCE7E4` | Фон опасного статуса |
| Focus | `#385E9D` | Контур клавиатурного фокуса |

Контраст обычного текста — не менее 4.5:1. Radius: 10px для controls, 16px для списков/полей, 20–28px для приоритетной ленты и sheet. Тень применяется только к приподнятым sheet/dialog и не заменяет границы.

### Типографика

- Display: `Newsreader` (fallback: Georgia, serif), weight 500; заголовок экрана 40–44px desktop и 36–38px mobile.
- UI/body: `DM Sans` (fallback: system-ui, sans-serif), основной текст 16px/24px; метаданные 12–13px.
- Цифры дат используют `font-variant-numeric: tabular-nums`.
- Длинные названия не обрезают критичную дату или статус: на mobile имя может переноситься, дата и статус имеют предсказуемую колонку/строку.

## Адаптивная компоновка

### Desktop (≥1024px)

Постоянная левая rail-навигация: «Продукты», «Рецепты», «Настройки», с текстом и SVG-иконкой. В нижней части — вторичная помощь и профиль. Контент справа: toolbar с CTA, крупный заголовок, горизонтальная лента трёх приоритетов, фильтры, затем таблично-списковый инвентарь. Активный пункт навигации имеет мягкую зелёную поверхность и текстовый признак.

### Tablet (640–1023px)

Rail переходит в компактную верхнюю навигацию. Лента срочности остаётся первой, список занимает всю ширину. Фильтры могут переноситься без горизонтального скролла.

### Mobile (<640px)

Постоянная нижняя панель содержит три top-level destinations: «Продукты», «Рецепты», «Настройки». Между ними отдельная центральная FAB «+». FAB открывает bottom sheet «Добавить продукт» с двумя действиями: «Ввести вручную» и «Заполнить по фото». Это не навигационная замена: основная навигация всегда доступна.

Sheet имеет видимую кнопку закрытия, закрывается по Escape и по клику на backdrop, возвращает фокус на FAB, не скрывает сфокусированный элемент и блокирует background interaction. На touch-устройствах поддерживается swipe-down только как дополнительный способ закрытия.

## Компоненты и состояния

| Компонент | Представление |
| --- | --- |
| `AppShell` | Desktop rail / tablet top navigation / mobile bottom navigation; skip-link и main landmark сохраняются. |
| `UrgencyRail` | Шалфейная поверхность, порядковый номер, название, место, текстовый относительный срок; максимум 3 продукта. |
| `ProductList` | Чёткие строки: продукт, хранение, тип и абсолютная дата, текстовый `StatusBadge`, context actions. |
| `StatusBadge` | SVG/визуальный маркер + текст + semantic tone; `active`, `attention`, `expired`, terminal, `research_required`. |
| `ProductForm` | Required-поля сначала, опциональные — в «Детали хранения»; label, help и ошибка возле соответствующего поля. |
| `PhotoUpload` / `DraftReviewForm` | Состояния файла, загрузки, распознавания, неопределённого поля и явного approve/reject; ручной путь остаётся доступен. |
| `LifecycleDialog` | Называет продукт и последствия «Использован»/«Выброшен», блокирует CTA при запросе, сохраняет ошибку в контексте. |
| `EmptyState` / `Skeleton` / `InlineAlert` | Отражают структуру будущего контента, одну понятную причину и одно уместное действие. |

`use by` после даты — «Срок истёк», красный status tone, не участвует в рецептах. `best before` после даты — «Требует внимания», янтарный tone и предупреждение, но остаётся доступным. `research_required` — нейтральное информационное состояние без медицинского или юридического вывода.

## Движение и обратная связь

Движение должно сообщать об изменении состояния, а не украшать интерфейс.

- Небольшие элементы на входе: opacity `0 → 1` и `translateY(8px → 0)` за 180ms, с шагом 40ms для списка, только при первом показе.
- Нажатие кнопки/FAB: scale `1 → .97 → 1` за 120–160ms; состояние loading отображается до результата и не зависит от animation-end.
- Bottom sheet: backdrop 160ms, sheet `translateY(24px) → 0` + opacity за 220ms; закрытие около 150ms. Открытие и закрытие остаются interruptible.
- Переходы между разделами — короткий crossfade 160ms, без сдвига layout и без потери фокуса.
- Toast: мягкое появление 180ms, не забирает фокус, сообщает результат через `aria-live`.
- При `prefers-reduced-motion: reduce` анимации и stagger отключаются: все состояния должны быть сразу читаемы и функциональны.

## Доступность и качество

- Только SVG-иконки единого stroke-стиля; icon-only controls получают доступное имя.
- Все интерактивные элементы — минимум 44px по высоте на touch-вьюпорте; keyboard order совпадает с визуальным.
- Видимый `:focus-visible`, 3px контур focus token, не перекрываемый sticky navigation или sheet.
- Body text не меньше 16px на mobile; нет hover-only функций; цвет никогда не является единственным носителем статуса.
- Проверяются 320px, 768px и 1440px: отсутствует горизонтальный overflow, нижняя панель не закрывает CTA, rail не ломает таблицу, а крупный текст не обрезается.

## Реализация и проверка

Изменения затрагивают только presentational слой `frontend/src/app.tsx`, общие компоненты и SCSS-токены/стили. Маршруты, запросы, валидация, локализация и fixture/API-интерфейсы сохраняются.

Проверки: существующие unit-тесты, новые тесты для семантической навигации и sheet, lint, production build, Playwright на 320/768/1440px и keyboard smoke-test. Визуальная проверка подтверждает обязательные loading, empty, error, `research_required`, form, draft и lifecycle states.
