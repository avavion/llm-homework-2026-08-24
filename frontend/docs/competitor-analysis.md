# Конкурентный анализ: интерфейс учёта продуктов и сроков

- **Продукт:** web-MVP помощника по использованию продуктов до истечения срока
- **Аудитория MVP:** один человек, который готовит дома
- **Дата исследования:** 26 августа 2026
- **Метод:** просмотр публичных сайтов, справочных страниц и карточек приложений конкурентов. Функции ниже — только заявленные источником; выводы и рекомендации помечены отдельно.

## Вывод для Front-End

Пользователь должен за несколько секунд ответить на три вопроса: «что есть», «что использовать первым» и «что сделать сейчас». Поэтому базовый экран — не каталог и не календарь, а инвентарь, отсортированный по срочности, с одним заметным действием «Добавить продукт».

Для MVP стоит взять у рынка быстрый путь добавления, визуальную срочность и привязку рецептов к запасу, но удержать интерфейс компактным. В отличие от большинства аналогов, необходимо явно и безопасно разделить `use by` / «годен до» и `best before` / «лучше употребить до».

## Цветовая система

Публичные страницы конкурентов сходятся в тёплой food-/eco-эстетике: природный зелёный как основной акцент, натуральные продуктовые фотографии и цветовая индикация срока. Точные hex-значения конкурентных приложений не заявлены в источниках; ниже не «палитра конкурента», а безопасная рабочая палитра, синтезированная для MVP. Она выдерживает информационный интерфейс, не делает зелёный единственным носителем смысла и отделяет риск от обычного акцента.

| Роль / токен | Значение | Применение |
| --- | --- | --- |
| `--color-brand-700` | `#166534` | Основная кнопка, активная навигация, ссылки с сильным акцентом |
| `--color-brand-600` | `#218B4C` | Hover, интерактивные иконки, положительный статус |
| `--color-brand-100` | `#DCFCE7` | Спокойный фон блока, тег «активен» |

| `--color-text` | `#17211A` | Основной текст, заголовки |

| `--color-border` | `#DDE5DC` | Границы, разделители, неактивные контуры |

| `--color-warning` | `#B45309` | `best before` после даты / «требует внимания» |
| `--color-warning-bg` | `#FFF7E6` | Фон предупреждения |

**Правило доступности.** Цвет никогда не должен быть единственным признаком статуса: рядом обязательны текстовый статус, иконка и дата. Для текста и интерактивных элементов требуется контраст не ниже WCAG AA; проверить реальные пары перед реализацией.

## Рекомендованная структура и паттерны

### 1. Экран «Мои продукты» — основной после входа

- Верхняя строка: заголовок, поиск и primary-кнопка **«Добавить продукт»**.
- Блок срочности перед списком: «Использовать сегодня» и «В ближайшие 3 дня»; максимум 3 карточки и ссылка «Все продукты».
- Фильтры в одну строку: место хранения, группа, статус; на мобильном — нижний sheet, на desktop — компактные chips.
- Список — сначала ближайшая значимая дата, затем название. В каждой строке: миниатюра/плейсхолдер, название, место хранения, тип даты, абсолютная и относительная дата, статус-бейдж, меню действий.
- Группировка по локации допустима только когда пользователь включил её: сортировка по срочности должна оставаться доступной по умолчанию.

### 2. Карточка продукта и действия жизненного цикла

- Показывать `use by` и `best before` как разные текстовые лейблы, а не только разные цвета.
- Для `best before` после даты: жёлтый блок «Проверьте упаковку, условия хранения и состояние продукта»; карточка остаётся в рецептах.
- Для `use by` после даты: красный блок «Срок истёк» и отсутствие CTA рецепта; доступны «Использован» и «Выброшен» с подтверждением.
- «Использован» — обычное вторичное действие; «Выброшен» — destructive, но не прятать настолько глубоко, чтобы нельзя было закончить цикл.

### 3. Добавление вручную и фото-черновик

- Ручная форма всегда является первым и полностью рабочим путём: название, тип даты и дата обязательны; количество, единица, группа и место — опциональны.
- Кнопка «Заполнить по фото» запускает отдельный шаг, не заменяет форму. Во время обработки показать прогресс и действие «Ввести вручную».
- Экран результата распознавания должен иметь пометку «Черновик — проверьте данные на упаковке», видимые значения уверенности/неопределённости при наличии и явные CTA **«Сохранить после проверки»** и **«Отклонить»**.
- Запрещено создавать продукт при загрузке фото или по завершении OCR: сохранение доступно только после явного подтверждения пользователя.

### 4. Рецепты

- Показывать только рецепты, в которые входят доступные и допустимые продукты; над рецептом — причина рекомендации: «Использует шпинат — 1 день до срока».
- Не показывать рецепт с просроченным `use by` ингредиентом. Для `best before` после даты добавлять понятное предупреждение, а не исключать молча.
- В MVP достаточно списка карточек без календаря и внешней выдачи: это соответствует уже определённой продуктовой границе.

| Ширина | Рекомендация |
| --- | --- |
| `≥ 1024px` | Боковая навигация: «Продукты», «Рецепты», «Настройки»; основной список 2/3 ширины и правая колонка «Использовать первым». |
| `640–1023px` | Верхняя навигация; один список с блоком срочности сверху; фильтры сворачиваются в popover. |
| `< 640px` | Фиксированная нижняя навигация; primary CTA доступен внизу или как FAB с текстовой подписью; строка продукта минимум в две строки, без hover-only действий. |

## Приоритет реализации

**P0 (MVP):** авторизация, список и фильтры, ручное добавление, карточка/редактирование, статусы и действия «использован/выброшен», настройки e-mail порога, ru/en, доступные состояния загрузки/пустого списка/ошибки.

**P1 (уже в продуктовой границе):** фото → проверяемый черновик → approve/reject; простые рецепты с объяснением приоритета.

**После MVP:** штрихкод, совместные домохозяйства, список покупок, календарь питания, автооценка срока, рекомендации диет и внешние рецепты.

## Проверяемые критерии hand-off

- [ ] С главного экрана ручное добавление достижимо одним действием; форма сохраняется без камеры и фото.
- [ ] В строке и деталях продукта всегда видны тип даты, дата и текстовый статус; цвет дополняет их.
- [ ] `use by` после срока визуально отличается от `best before` после даты и не получает CTA рецепта.
- [ ] Фото создаёт только черновик; до подтверждения нет сообщения об успешно добавленном продукте.
- [ ] Интерфейс работоспособен с клавиатурой, видимым focus и текстовым эквивалентом всех цветовых статусов.
- [ ] Ширины 320px, 768px и 1440px проверены без горизонтальной прокрутки основного контента.

## Ограничения исследования и следующий шаг

Это конкурентный desk research, а не тестирование приложений с реальными пользователями. Маркетинговые заявления (включая аудиторию, оценки и экономический эффект) не использовались как доказательство ценности. Следующий продуктовый шаг — 5–7 коротких usability-тестов интерактивного прототипа на P0-потоках: ручное добавление, интерпретация двух типов дат, завершение продукта и проверка фото-черновика.
