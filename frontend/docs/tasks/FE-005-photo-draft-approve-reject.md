# FE-005 — Фото-черновик с проверкой и approve/reject

- **Исполнитель:** Senior Frontend Developer
- **Статус:** ready после зависимостей
- **Зависимости:** FE-001, FE-002, FE-004, BE-006
- **Timebox:** 3 рабочих дня
- **Technical review:** approved, круг 1/2; [запись](../reviews/2026-08-26-frontend-technical-review.md)

## SMART-цель

За три рабочих дня реализовать UI загрузки фото и проверки server-side черновика: распознанные поля попадают в редактируемую форму, а продукт появляется в инвентаре только после успешного явного `approve`. `reject`, ошибка сети или ошибка распознавания не создают продукт и позволяют перейти к ручному вводу.

## Границы

- Использовать только согласованные endpoints recognize/approve/reject BE-006.
- Не подтверждать продукт автоматически, не показывать недостоверный текст OCR как факт и не утекать исходные фото в публичные URL/логи.

## Приёмка

- [ ] До `approve` интерфейс помечает результат как «Черновик — проверьте данные на упаковке».
- [ ] Пользователь может исправить каждое доступное поле перед approve.
- [ ] `reject` возвращает к форме или удаляет черновик с понятным результатом и без нового продукта.
- [ ] При timeout/ошибке ручной путь остаётся рабочим; повтор не отправляет одновременные approve.

## QA

Playwright с fixtures: recognize success, плохо заполненный draft, reject, timeout, double-click approve. Security: 403/404 draft не раскрывает содержимое.
