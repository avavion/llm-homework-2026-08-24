# FE-001 — UX-система и адаптивная спецификация

- **Исполнитель:** Senior UI/UX Designer
- **Статус:** ready
- **Зависимости:** —
- **Timebox:** 2 рабочих дня
- **Technical review:** approved, круг 1/2; [запись](../reviews/2026-08-26-frontend-technical-review.md)

## SMART-цель

До конца двух рабочих дней подготовить в `frontend/docs/` спецификацию экранов и состояний для web-MVP на русском и английском: авторизация с выбором страны, список продуктов, карточка, ручная форма, фото-черновик, рецепты и настройки. Спецификация должна позволить разработчику воспроизвести поведение на ширинах 320px, 768px и 1440px без неоговорённых визуальных решений.

## Границы

- Включить семантические токены из `competitor-analysis.md`, выбор страны и отображение группы регулятора, правила `use by` / `best before`, focus, loading/empty/error и destructive-действия.
- Для режима `research_required` описать безопасное состояние «Правило уточняется»: нет автоматического статуса, e-mail-расписания, медицинского или юридического вывода.
- Не проектировать push, семейный доступ, штрихкод, покупки, календарь и внешние рецепты.

## Приёмка

- [ ] У каждого экрана есть цель, primary action, пустое, загрузочное и ошибочное состояние.
- [ ] Для двух типов даты описаны текст, иконка, цвет и последствие для рецепта.
- [ ] Фото оставляет ручную форму доступной и требует явного `approve` или `reject`.
- [ ] Выбор страны понятен при регистрации и в настройках; для `research_required` отображается безопасное состояние без ложного вывода о пригодности.
- [ ] Для 320/768/1440px определены навигация, фильтры и действия без hover-only управления.

## QA

QA сверяет реализованные экраны с этой спецификацией скриншотами Playwright на трёх viewport.
