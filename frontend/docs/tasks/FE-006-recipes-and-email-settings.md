# FE-006 — Рецепты и настройки e-mail-напоминаний

- **Исполнитель:** Senior Frontend Developer
- **Статус:** blocked до согласования HTTP-контракта
- **Зависимости:** FE-001, FE-002, FE-003, BE-005, согласованный HTTP-контракт recipes и notification settings
- **Timebox:** 3 рабочих дня
- **Technical review:** approved, круг 1/2; [запись](../reviews/2026-08-26-frontend-technical-review.md)

## SMART-цель

За три рабочих дня добавить экран простых собственных рецептов и настройку порога e-mail-напоминаний. Рекомендация должна объяснять, какой имеющийся продукт она помогает использовать, и не должна показываться для просроченного `use by`; UI не позволит выбрать порог меньше 60 минут.

## Границы

- Использовать детерминированные first-party рекомендации и eligibility backend, когда согласованы endpoint выдачи рецептов, чтения/изменения notification settings, DTO и коды ошибок. BE-005 сам по себе пока публикует сервисные, а не HTTP-контракты; до фиксации интеграция блокирована.
- Канал MVP — только e-mail. Не добавлять push, внешние рецепты, LLM-рецепты или календарь питания.

## Приёмка

- [ ] Карточка рецепта показывает причину приоритета и доступные ингредиенты.
- [ ] Expired `use by` не становится причиной рекомендации; attention `best before` сопровождается предупреждением.
- [ ] Порог ниже 60 минут недоступен в control и корректно отображает ошибку backend при прямом ответе API.
- [ ] У рецептов и настроек есть loading, empty и error states.
- [ ] До согласования HTTP-контракта задача не начинает production-интеграцию и остаётся `blocked`; тестовые fixture не считаются заменой API.

## QA

Playwright: список рецептов, пустая выдача, expired/attention, нижняя граница 60 минут и error API; проверка на mobile и desktop.
