# FE-004 — Ручное добавление продукта

- **Исполнитель:** Senior Frontend Developer
- **Статус:** in progress (fake POST до BE-004)
- **Зависимости:** FE-001, FE-002, BE-004
- **Timebox:** 3 рабочих дня
- **Technical review:** approved, круг 1/2; [запись](../reviews/2026-08-26-frontend-technical-review.md)

## SMART-цель

За три рабочих дня реализовать доступную форму создания продукта, позволяющую авторизованному пользователю сохранить название, тип даты и дату, а при необходимости — количество, единицу, группу и место хранения. Ошибка в необязательной фотографии не мешает полностью ручному вводу. Редактирование сохранённого продукта не входит в задачу, пока отдельный account-scoped API не согласован с backend.

## Границы

- Обязательные поля: `name`, `date_type`, `expiry_date`; допустимы только `use_by` и `best_before`.
- Ошибки валидации API должны быть привязаны к полям либо показаны как доступное общее сообщение.

## Приёмка

- [ ] Submit с пустым каждым обязательным полем невозможен и содержит текст ошибки.
- [ ] Сохранение корректной формы создаёт продукт один раз и возвращает к обновлённому инвентарю.
- [ ] В форме текстом объяснена разница между двумя типами дат.
- [ ] Все элементы имеют label, logical tab order и не требуют камеры/мыши.

## QA

Component-тесты валидации и request state. Playwright: пустые поля, ошибка API, success, английская локаль и мобильный viewport.
