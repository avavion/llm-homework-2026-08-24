# BE-004 — Учёт продуктов и жизненный цикл

**Исполнитель:** Senior Backend Developer · **Статус:** draft · **Зависимости:** BE-001, BE-003 · **Timebox:** 3 дня

## SMART-цель

Дать пользователю API для создания, просмотра и завершения собственных продуктов с обязательными полями: имя, тип даты и дата.

## Объём и приёмка

- Создание, список, просмотр, `used` и `discarded`; необязательны количество, единица, группа, хранение и порог e-mail.
- Отсутствие обязательного поля возвращает 400; допустимы только `use_by` и `best_before`.
- Другой account ID не видит продукт.
- `used` и `discarded` сохраняют разные финальные статусы и время завершения.

## Контроль

**Ревью Developer:** модель, даты, транзакции и account-scoping.  
**QA:** неверные поля, чужие ID, повторное финальное действие и утечки.
